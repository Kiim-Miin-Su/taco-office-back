# seed — 화면이 쓰는 **단일 진실원**

프론트는 목 데이터를 들고 있지 않는다. 화면이 보는 값은 전부 이 시드가 넣은
**실제 Postgres 행**이고, API 를 통해서만 내려간다.

그래서 진짜 데이터로 바꿀 때 프론트는 **한 줄도 고치지 않는다** — 같은 표, 같은 API,
행만 달라진다. 이것이 「자동 전이」다.

## 돌리는 법

```bash
npm run migration:run     # 표를 먼저 만든다
npm run seed              # 이 폴더의 데이터를 넣는다
npm run seed -- --reset   # 기존 시드 행을 지우고 다시 넣는다
```

## 규칙 넷

1. **결정적이다.** 난수를 쓰지 않는다. 같은 명령은 같은 행을 만든다 —
   화면 스냅샷과 테스트가 흔들리지 않게.
2. **기준일이 고정이다.** `SEED_TODAY` (2026-08-28) 를 기준으로 상대 날짜를 만든다.
   「오늘 수업」·「어제 리포트」·「3일 지남」이 언제 돌려도 성립한다.
3. **규칙을 지킨다.** 리포트 상태·지각 차감·정산은 `src/lib/rules.ts` 를 그대로 통과하는
   값만 넣는다. 화면에서만 그럴듯한 데이터는 만들지 않는다.
4. **운영 DB 에서는 안 돈다.** `DATABASE_URL` 에 `prod` 가 들어 있으면 거부한다.

## N-16 과 다른 것

N-16(초기 데이터)은 **운영을 무엇으로 시작할지**의 결정이다. 이 시드는 **개발·시연용**이고
운영 데이터가 아니다. 둘을 섞지 않는다.
