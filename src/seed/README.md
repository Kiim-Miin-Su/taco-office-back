# seed — 개발·시연용 DB 데이터

프론트는 API를 통해 **실제 Postgres 행**을 읽는다. 시드는 개발·시연의 시작 데이터이며,
현재 상태의 단일 진실원은 사용자가 수정한 내용을 포함한 DB다. 시드 파일이 운영 레코드보다 우선하지 않는다.

그래서 진짜 데이터로 바꿀 때 프론트는 **한 줄도 고치지 않는다** — 같은 표, 같은 API,
행만 달라진다. 시드와 화면을 분리한 구조이며 업무 상태의 자동 전이와는 별개다.

## 돌리는 법

먼저 격리 로컬 `DATABASE_URL`을 지정한다. 기존 `.env.local`에 운영 DB가 있으면 실행하지 않는다.
`--reset`은 시드 대상 표의 기존 행을 지우므로 초기화 대상과 권한이 확인됐을 때만 사용한다.

```bash
npm run migration:run     # 표를 먼저 만든다
npm run seed              # 이 폴더의 데이터를 넣는다
npm run seed -- --reset   # 기존 시드 행을 지우고 다시 넣는다
```

## 규칙 넷

1. **결정적이다.** 난수를 쓰지 않는다. 같은 명령은 같은 행을 만든다 —
   화면 스냅샷과 테스트가 흔들리지 않게.
2. **기본 기준일은 오늘(KST)**이다. 과거 재현은 `SEED_TODAY`를 명시한다 (`src/seed/base.ts`).
   같은 날짜를 지정해야 같은 상대 날짜 데이터를 재현할 수 있다.
3. **규칙을 지킨다.** 리포트 상태·지각 차감·정산은 `src/lib/rules.ts` 를 그대로 통과하는
   값만 넣는다. 화면에서만 그럴듯한 데이터는 만들지 않는다.
4. **기본은 로컬 대상만 허용한다.** `src/lib/target.ts`의 `assertWritableTarget()`이 호스트/DB를 판정한다.
   관리형·알 수 없는 호스트에는 DB 이름을 정확히 확인하는 별도 override가 필요하다.
   이 안전장치가 운영 초기화 승인을 대신하지 않으며, `prod` 문자열 유무만 검사하는 방식은 폐기됐다.

## N-16 과 다른 것

N-16(초기 데이터)은 **운영을 무엇으로 시작할지**의 결정이다. 이 시드는 **개발·시연용**이고
운영 데이터가 아니다. 둘을 섞지 않는다.
